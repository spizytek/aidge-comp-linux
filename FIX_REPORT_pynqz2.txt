  This matches README.md line 193, which documents loading with
  "fpgautil -b fpga.bin".

3. HARDCODED AXI AxSIZE IN THE AXIL->AXI ADAPTER
--------------------------------------------------------------------------------

Issue:
  axil_axi_adapter.vhd emitted AxSIZE = "100" (16 bytes per beat) on both the
  AW and AR channels, regardless of AXI_DATA_WIDTH. That encoding is only valid
  for a 128-bit bus; the Pynq-Z2 memory path is 64-bit, so the PS7 was told each
  beat was twice as wide as it really is, which corrupts burst address
  advancement.

Fix:
  Added a width-to-encoding function and used it at both call sites.

  submodules/locod-fpga/src/axil_axi_adapter/rtl/axil_axi_adapter.vhd,
  lines 141-155 (new function):

      function axi_size(width : integer) return std_logic_vector is
      begin
          case width is
              when 8   => return "000";
              when 16  => return "001";
              when 32  => return "010";
              when 64  => return "011";
              when 128 => return "100";
              when 256 => return "101";
              when 512 => return "110";
              when others => return "111";
          end case;
      end function;

LOADING THE BITSTREAM ON PYNQ-Z2 (ZYNQ-7000)
--------------------------------------------------------------------------------

IMPORTANT: the mainline zynq-fpga driver requires the bitstream in
BYTE-SWAPPED .bin form (sync word 66 55 99 AA). The .bin produced by
"write_bitstream -bin_file" is big-endian (sync word AA 99 55 66) and is
rejected by the kernel with:

    fpga_manager fpga0: Invalid bitstream, could not find a sync word.
    Bitstream must be a byte swapped .bin file

Xilinx fpgautil performs this swap internally on Zynq. If fpgautil is not
installed (e.g. stock PYNQ image), do the swap manually:

    sudo python3 - <<'PY'
    src = '/home/xilinx/mytest/fpga.bin'
    dst = '/lib/firmware/fpga_swapped.bin'
    data = open(src, 'rb').read()
    out = bytearray(len(data))
    for i in range(0, len(data), 4):
        out[i:i+4] = data[i:i+4][::-1]
    open(dst, 'wb').write(out)
    PY

    echo 0 | sudo tee /sys/class/fpga_manager/fpga0/flags
    echo fpga_swapped.bin | sudo tee /sys/class/fpga_manager/fpga0/firmware
    cat /sys/class/fpga_manager/fpga0/state      # expect: operating

    sudo ./locod-cpu

Note: the "FPGA execution time" reported by the test (~0.7 ms) includes the
register accesses, DDR copies and 1 us polling loop, so it is much larger than
the 7 us CPU time for this tiny 16x16 workload. This is expected and is not a
sign of a problem.
